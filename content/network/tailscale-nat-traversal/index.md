> 原文：Tailscale《[How NAT traversal works](https://tailscale.com/blog/how-nat-traversal-works/)》——这是 NAT 穿透领域被引用最多的科普长文。本文是其核心原理的中文导读（完整中文译本团队内部留存）；建议结合《[双重 NAT 问题模型](/network/dual-nat-traversal/)》与《[花生壳拆解](/network/oray-shell-teardown/)》阅读，三篇互为补充。

## 1. 问题的本质：互联网是单向门

互联网上的双向通信要求**双向路径可达**，但 NAT 与有状态防火墙的默认策略是"只放行我主动发起的连接"。两台各自躲在 NAT 后面的设备想直连，核心矛盾就一句话：**双方都需要先收到对方的包，才肯放行对方的包**。

## 2. STUN：打洞的标准姿势

STUN（Session Traversal Utilities for NAT）服务器的角色很简单：**告诉你"你在互联网上长什么样"**。

1. 设备 A 向 STUN 服务器发一个请求；
2. STUN 服务器把**看到的源地址:端口**（即 NAT 映射后的公网端点）告诉 A；
3. 双方通过某个渠道（Tailscale 里是协调服务器）交换各自的公网端点；
4. 双方**同时**向对方的公网端点发包——每个 NAT 都看到了"出站包"，为该端点打开了回程入口——洞就打穿了。

第 4 步的"同时"很关键：只要有一方的首包先到、而对方还没向它发过包，就会被对方的防火墙丢弃。所以实现上通常是**双方持续互发包直到双向确认**。

## 3. NAT 的四个维度：决定打洞难度

传统 full cone / restricted cone / symmetric 的分类法容易误导——Tailscale 用两个正交维度重新划分：

| 维度 | 行为 | 对打洞的影响 |
|---|---|---|
| **映射**（对 STUN 服务器呈现什么） | 端点无关（同一内网端点对任何目标都复用同一映射）/ 端点相关（目标变了映射就变） | 端点无关 → 交换到的公网端点直接可用；端点相关 → 交换到的端点对"对端"无效 |
| **过滤**（允许谁进来） | 端点无关 / 地址相关 / 地址+端口相关 | 决定"先向对方发包"是否足够打开回程 |

好消息是**大多数 NAT 是端点无关映射**（"easy NAT"），双方交换 STUN 结果后互发即通。坏消息是当**一端是端点相关映射**（"hard NAT"）时，STUN 得到的端点只对 STUN 服务器有效，对对端无效——这时就要靠下面的手段。

## 4. 困难 NAT 的招数：生日攻击与端口预测

对付 hard NAT，Tailscale 用了一个反直觉的统计武器——**生日悖论攻击**：

- hard NAT 一侧虽然换目标就换端口，但**端口分配通常是顺序的**；
- soft NAT 一侧开放大量本地端口（如 256 个），对 hard NAT 侧预测的端口范围**同时发包**；
- 按生日悖论，只要预测范围与端口散布有交集，命中概率随端口数平方根增长——256 个端口对 64 个预测端点的命中率可以到 50% 以上；
- 防御方对策：NAT 把**外部端口随机化**，让预测失效（这也是评估 NAT 设备质量的一个指标）。

## 5. 保活：洞是有寿命的

NAT 映射是**状态**，闲置就会被回收（UDP 常见 30s~几分钟，TCP 更长）。打穿的连接必须周期性发包保活——Tailscale 默认按需保活，空闲连接用低频心跳维持映射。保活周期必须**短于路径上最短的映射寿命**，这在多层 NAT（设备 NAT + 运营商 CGNAT）下取最严格值。

## 6. 打不通怎么办：DERP 中继兜底

现实里总有一小部分组合（双 hard NAT、UDP 全封的环境）打不穿。Tailscale 的答案是 **DERP**（Distributed Embedded Relay Power）：全球中继节点网络，流量走**中继 + 端到端加密**（WireGuard 加密不变，中继只见密文）。设计要点：

- 先尝试 P2P，失败自动回落 DERP，用户无感；
- DERP 走 **TLS over 443**——在最敌意的网络（只放行 HTTPS 的酒店/企业网）里也能通；
- 直连能通时自动升级回 P2P，省中继带宽。

## 7. 小结

把 Tailscale 的策略串成一句话：**先 STUN 交换端点互打发洞，困难组合上生日攻击预测端口，全程保活，打不通回落 TLS 中继**。它把《[双重 NAT 问题模型](/network/dual-nat-traversal/)》里的三条路线（打洞/中继/组网）工程化成了一个自动决策系统——这也是自建穿透方案最值得抄的架构思想。
