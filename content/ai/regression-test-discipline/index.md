> 场景：一套会改生产服务器状态的脚本（VPN 初始化、防火墙配置、设备注册），每次改动都要回归。挑战：测试既要能验证"改了服务器状态的脚本"，又绝不能在测试环境里真的改状态。以下纪律来自多轮实战迭代。

## 纪律一：PASS / SKIP / FAIL 三态分账，绝不合并

最容易犯的错是把"没跑"当"通过"：

```bash
# 反模式
run_test() { cmd >/dev/null 2>&1 && passed=$((passed+1)) || passed=$((passed+1)); }  # 反正都算过
```

正确姿势是三态独立计数，报告末尾分别打印：

- **PASS**：断言成功；
- **SKIP**：环境不满足（如二进制缺失、需要 root），**显式列出跳过原因**；
- **FAIL**：断言失败，输出期望 vs 实际。

一条铁律：**SKIP 率超过阈值的测试批次整体视为无效**——大量 SKIP 说明夹具坏了，"全绿"是错觉。

## 纪律二：系统级命令走白名单（shim 化）

被测脚本会调用 `apt`、`systemctl`、`wg`、`ip` 这类系统命令。测试夹具的做法是把这些命令**替换为记录型 shim**：

```bash
# 夹具：PATH 前置一个 stub 目录，系统命令变成"记录调用 + 返回预设值"
stub/apt()  { echo "apt $*" >> "$TEST_CALLS"; return 0; }
```

但 shim 不能是"万能为真"——**白名单约束调用范围**：

- 允许的调用（如 `apt install wireguard`）记录后返回成功；
- 危险调用（如 `apt upgrade`、`reboot`）返回失败并**置 FAIL**——被测脚本不该碰它们；
- **断言"不调用"和断言"调用"同样重要**：一次回归的核心断言往往是"初始化脚本在已有配置时绝不能重启接口"。

## 纪律三：夹具三件套

1. **临时目录沙箱**：所有文件操作重定向到 `mktemp -d`，测试结束清场（失败时保留现场并打印路径）；
2. **预设状态注入**：通过环境变量喂"已有配置"（如预置 `wg0.conf` 验证幂等分支），覆盖"全新安装/重复安装/配置残留"三类入口；
3. **本地隔离回归**：整套测试在一台开发机上零依赖可跑（`bash test_xxx.sh` 一条命令），CI 与人工都跑同一份。

## 纪律四：测试的测试

夹具本身会坏（shim 路径错了、预设文件没生成）。两个防线：

- 每个夹具带**自检用例**（喂一个已知会失败的调用，断言它真的 FAIL）；
- 断言计数守恒：`PASS + SKIP + FAIL == 总用例数`，对不上直接报夹具错误。

## 沉淀

这套纪律的产出是：改动运维脚本从"人肉上服务器试"变成 `bash test_x.sh` 三秒出报告；上线事故归零不是靠小心，是靠"危险调用必然红灯"。它和《[契约驱动的 AI 协作开发](/ai/contract-driven-ai-dev/)》是同一哲学：**把'不该发生的事'变成断言，而不是变成期望**。
